# NNUE Architecture Specification: Luminex V13

## 1. General Metadata
- **Network Name**: Luminex V13
- **Target Engine / Application**: Luminex (v6.2+)
- **Primary Use Case**: Chess Position Evaluation
- **Weight Quantization Scheme**: Post-hoc, global scales (int16 feature transformer, int8 tail); export contract in §8
- **Internal Output Scale**: int64 intermediate → int32 centipawns

### Constants (pinned; `FP<dtype, s>` = value stored in dtype multiplied by s)
| Symbol | Value | Meaning |
|---|---|---|
| `FT_WSCALE` | 8192 | feature-transformer weight scale = SCReLU clip ceiling |
| `QA` | 8192 | activation clip bound (`clamp(in, 0, QA)`) |
| tail weight bound | ±127 (int8) | all dense layers L1–L5 |
| activation input to dense layers | 0..127 (requantized) | after the §5 requantization step |
| `V_CLAMP` | 8191 | FM latent component bound (n=32 derivation in §3) |
| `FM_SHIFT` | 22 | FM narrowing right-shift (derivation in §3) |
| `LIN_SCALE` | 32 | DOSL weight scale; `lin` accumulator int32 |
| eval scale | 400 | sigmoid(cp/400) training space |

## 2. Input Features & Transformer Layer
- **Feature Set Name**: HalfKAv2_hg-f (king-bucketed, factorized)
- **Input Feature Dimension**: `[24576]` per perspective (Sparse boolean)
- **Feature Index Formula** (exact, matches engine `halfka_idx`):
  `idx = KingBuckets[orient(pov, ksq)] * 768 + p_idx * 64 + orient(pov, sq)`
  where `p_idx = piece_type*2 + (color != pov)` (both colors visible), `orient` mirrors squares by king file (kfile ≥ 4 → XOR 7) and vertical flip (XOR 56) for the black perspective, and `KingBuckets[64]` maps oriented king squares to buckets
- **Feature Breakdown**:
  1. **Feature Group 1**: base HalfKAv2_hg — 32 effective king buckets × 12 piece-color planes × 64 oriented squares = 24,576
  2. **Feature Group 2**: bucket-count factorizer — the base 32 king buckets collapse to fewer (bucket count is an ablation-gated knob: 4 initial, 8/16 to test); factorized (virtual) features share transformer columns across buckets. Physical weight rows and physical active features stay ≤ 32 per perspective; virtual features alias onto physical columns
- **Perspective Symmetry**: Dual Perspective (`side-to-move` / `other-side`)

---

## 3. Perspective Accumulator Subnet
- **Input Dimension**: `[24576]` (Sparse boolean)
- **Output Dimension**: `[768]` per perspective (combined `[1600]` with interaction vectors, see §4)
- **Layer Breakdown**:
  - `Sparse Linear`: Input `[24576]` -> Output `[768]` | Weights: `FP<i16, 1>` scaled by FT_WSCALE at export, Bias: `FP<i16>`
  - **Accumulator invariant** (saturating int16 is exact post-activation): the SCReLU window [0, 8192] lies 4× below int16 saturation (±32,767). Any lane that saturates was already ≥ QA (or ≤ 0), so its SCReLU output is identical to the unsaturated value — saturation is masked by the activation, and make/unmake path drift only occurs where the post-activation output is constant. Verified exhaustively on 6,000 real perspectives in the current engine
  - `Activation`: SCReLU `clamp(in, 0, 8192)²`, square computed in `int32` (max 8192² = 67,108,864 fits), then requantized to 0..127 for the dense input (see §5)
  - **Interaction Block (V13)** — Factorization-machine latent sums, computed from the **active input feature set** (not the accumulator output), per perspective:
    - Per-feature latent vectors `v_i ∈ R^32` (`FP<i16>`, k = 1..32), running sums per component, **exact int64 accumulation (no saturation, fully invertible)**: `S_k = Σ_{i active} v_{i,k}`, `Q_k = Σ_{i active} v_{i,k}²` — no reduction over k
    - Bounds sized for **n = 32 physical active features** (32 men ⇒ 32 features per perspective; virtual factorized features alias physical columns and do not raise the count): `|S_k| ≤ 32·8191 = 262,112`; `Q_k ≤ 32·8191² = 2,146,959,392 < int32max` (margin 524,255) — the `V_CLAMP = 8191` bound makes `Q_k` int32-safe by construction; `S_k²` (max ≈ 6.87e10, ~32× int32max, ~2.5 orders) is computed only in int64
    - `I_k = ½(S_k² − Q_k)` computed in int64, narrowed by `>> 22`: worst case `½·(32·8191)² / 2²² = 8191.98` — the shift maps the absolute worst case exactly onto the 8192 activation window. Single active feature yields exactly `I_k = 0` (unit-test invariant). Arithmetic shift on negative `I_k` rounds toward −∞; the ≤1-ulp bias is accepted
    - *(Deferred variant, not V13: forward-time products `A⊙B` of accumulator halves — would produce 384-wide interaction vectors per perspective, concat 2304, and respecify §4/§5)*

## 4. Subnet Selection & Bucketing Logic
- **Routing Factor**: total men on board, kings included (range 2..32 by chess law — promotions convert, never clone)
- **Bucket Selection Logic** (truncating integer division, clamped):
  `m = clamp(men, 2, 32); Index = clamp((m - 1) / 4, 0, 7)`
  Start position: m=32 → bucket 7. Bare kings: m=2 → bucket 0. All 8 buckets reachable
- **Number of Buckets**: `8` (Main Subnets `0` through `7`)
- **Combined Perspective State** (concat order pinned): `[acc_stm(768), I_stm(32), acc_nstm(768), I_nstm(32)]` = `[1600]`, fed to the selected Main Subnet
- **Soft Interpolation (experiment flag, default OFF)**: `t = ((m-1) - 4·b) / 4 ∈ [0,1)`, `eval = (1-t)·head[b] + t·head[min(b+1, 7)]` — the clamp forces pure `head[7]` at b=7 (the start position blends nothing: t=0 at m=32)

---

## 5. Main Subnet Architecture
Dense-layer inputs are the requantized activations (0..127) and shifted interaction terms (bounded by 8192-window alignment), weights int8 (±127). Worst-case dot product: `1600 × 127 × 127 = 25,806,400` — 83× int32 headroom by construction.

| Layer Index | Layer Type | Input Shape | Output Shape | Activation / Operation | Fixed-Point Type |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **L1** | Dense Linear | `[1600]` | `[16]` | None | `FP<i32>` (bound above) |
| **L2** | Activation + Requant | `[16]` | `[16]` | SCReLU in i32, store requantized i8 | `FP<i8, 127>` |
| **L3** | Dense Linear | `[16]` | `[32]` | None | `FP<i32>` |
| **L4** | Activation + Requant | `[32]` | `[32]` | SCReLU in i32, store requantized i8 | `FP<i8, 127>` |
| **L5** | Dot Product | `[32]` | `[1]` | Output Dot Product | `FP<i32>` |

## 6. Output Conversion & Post-Processing
- **DOSL Linear Head** (parallel branch, not summed with the main output): per-feature scalar weights (`FP<i16, 32>`) over the same 24,576 index space, exact **int32** accumulator per perspective (max 32 × 32,767 ≈ 983K), `cp = lin[stm] / 32`. qsearch stand-pat reads it without running the Main Subnet
- **Perspective Average Shortcut**: None
- **Output Addition**: None (bucket head output only)
- **Final Rescaling Formula** (int64 intermediate — int32 multiply would wrap at realistic multipliers):
  $$
  \text{Value} = \frac{\text{int64}(in) \times \text{Multiplier}}{\text{Denominator}}
  $$
- **Final Return Type**: Signed Integer (`int32`) / Centipawns

---

## 7. Update Rules (incremental paths)
- **Feature flip** (quiet move, capture, promotion): for each flipped feature index i, per perspective: accumulator lane add/sub `w_i` (saturating i16, exact per §3 invariant); `S_k ±= v_{i,k}`, `Q_k ±= v_{i,k}²` (int64, exact); DOSL `lin ±= lw_i` (int32). O(features flipped) × O(1)
- **King move / castling** (king square changes): all features of the mover's perspective re-index — full refresh of that perspective's accumulator, S, Q, and lin (32 feature rows); the other perspective is untouched
- **En passant**: mover pawn flip + captured pawn flip off the capture square
- **Side-to-move change**: no recomputation — the concat order and `lin[stm]` index swap perspectives only

---

## 8. Export Contract
- Trained float weights quantized post-hoc with the §1 constants; Multiplier/Denominator chosen so the head output maps to the sigmoid(cp/400) training scale
- Export-time asserts (fail the build, not the game): `32 · V_CLAMP² < 2³¹`; `max|I| >> 22 ≤ 8192` over worst-case n=32; all dense-layer weight bytes within ±127; single-feature FM probe returns exactly 0; bucket index ∈ [0,7] for m ∈ [2,32]
- The per-channel-scale quantizer upgrade is planned but not part of this contract
