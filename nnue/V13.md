# NNUE Architecture Specification: Luminex V13

## 1. General Metadata
- **Network Name**: Luminex V13
- **Target Engine / Application**: Luminex (v6.2+)
- **Primary Use Case**: Chess Position Evaluation
- **Weight Quantization Scheme**: Post-hoc, global scales (int16 feature transformer at `FT_WSCALE = 8192`, int8 tail ±127); export asserts bound every requant path
- **Internal Output Scale**: int64 intermediate → int32 centipawns

---

## 2. Input Features & Transformer Layer
- **Feature Set Name**: HalfKAv2_hg-f (king-bucketed, factorized)
- **Input Feature Dimension**: `[24576]` per perspective (Sparse boolean)
- **Feature Breakdown**:
  1. **Feature Group 1**: base HalfKAv2_hg — 32 effective king buckets × 12 piece-color planes × 64 oriented squares = 24,576; index `KingBuckets[orient(pov, ksq)] * 768 + p_idx * 64 + orient(pov, sq)` with `p_idx = piece_type*2 + (color != pov)`, `orient` mirroring by king file (kfile ≥ 4 → XOR 7) and vertical flip (XOR 56) for black — exact match to engine `halfka_idx`
  2. **Feature Group 2**: bucket-count factorizer — the base 32 king buckets collapse to fewer (bucket count is an ablation-gated knob: 4 initial, 8/16 to test); factorized (virtual) features share transformer columns across buckets. Physical weight rows and physical active features stay ≤ 32 per perspective; virtual features alias onto physical columns
- **Perspective Symmetry**: Dual Perspective (`side-to-move` / `other-side`)

---

## 3. Perspective Accumulator Subnet
- **Input Dimension**: `[24576]` (Sparse boolean)
- **Output Dimension**: `[768]` per perspective (combined `[1600]` with interaction vectors, see §4)
- **Layer Breakdown**:
  - `Sparse Linear`: Input `[24576]` -> Output `[768]` | Weights: `FP<i16, 1>` scaled by FT_WSCALE at export, Bias: `FP<i16>`
  - **Accumulator invariant** (saturating int16, exact under stated conditions): the SCReLU window [0, 8192] lies 4× below int16 saturation (±32,767). Saturation is masked by the activation WHILE the true lane value stays outside the window. A saturated lane whose true value later re-enters [0, 8192] drifts by the accumulated saturation loss — exactness on re-entry paths is NOT claimed. Bounded-drift argument: full perspective refreshes on every king move (the most frequent re-indexing event) reset all lanes to exact values, bounding any drift chain to the ply gap between king moves. Verified exact on 6,000 real game perspectives; the adversarial saturation→re-entry sequence (deep-saturate a lane, retract stepwise, compare against an exact int32 reference at EVERY intermediate ply) is a mandatory unit test — if it ever fails on real weights, the fallback is exact int32 accumulators (2× memory)
  - `Activation`: SCReLU `clamp(in, 0, 8192)²`, square computed in `int32` (max 8192² = 67,108,864 fits), requantized `min(sq >> 19, 127)` for the dense input
  - **Interaction Block (V13)** — Factorization-machine latent sums, computed from the **active input feature set** (not the accumulator output), per perspective:
    - Per-feature latent vectors `v_i ∈ R^32` (`FP<i16>`, k = 1..32), running sums per component, **exact int64 accumulation (no saturation, fully invertible)**: `S_k = Σ_{i active} v_{i,k}`, `Q_k = Σ_{i active} v_{i,k}²` — no reduction over k
    - Bounds sized for **n = 32 physical active features** (32 men ⇒ 32 features per perspective; virtual factorized features alias physical columns and do not raise the count): `|S_k| ≤ 32·8191 = 262,112`; `Q_k ≤ 32·8191² = 2,146,959,392 < int32max` (margin 524,255) — the `V_CLAMP = 8191` bound makes `Q_k` int32-safe by construction; `S_k²` (max ≈ 6.87e10, ~32× int32max, ~2.5 orders) is computed only in int64
    - Raw interaction value `I_k = ½(S_k² − Q_k)` (int64, the ONLY meaning of the bare symbol `I_k`). Its window-aligned form is a distinct symbol: `Î_k = I_k >> 22`. The worst case maximizes the COMBINED expression: n same-sign max-magnitude features give `I_k,max = C(32,2)·8191² = 496 × 67,092,481 = 33,277,870,576`, and `>> 22` maps it to `Î_k = 7,934` — 97% of the 8192 activation window (S_k² alone would be ~32× int32max, i.e. 1.5 orders). Single active feature yields exactly `I_k = 0` (unit-test invariant). Arithmetic shift on negative `I_k` rounds toward −∞; the ≤1-ulp bias is accepted. Requantization is branch-specific (the two branches differ by three orders of magnitude — a shared divisor is wrong). CANONICAL form — a function of the STORED `Î_k`: `clamp(Î_k >> 6, -127, 127)` (extremes +123 / −4). Equivalent when computed from raw in one expression: `clamp(I_k >> 28, -127, 127)`, by shift associativity (floor-of-floor composes exactly). Implementations that store `Î_k` (the §4 concat state) MUST use the `>>6` form — applying `>>28` to `Î_k` would zero the branch; the export assert checks both forms agree. The signed range is real: mixed-sign v's give Q_k > S_k². Signed slots ride the u8 dense operand via a +128 zero point; since `Σ(x_j+128)·w_j = Σx_j·w_j + 128·Σw_j`, the correction is SUBTRACTED: `bias_eff[row] = bias[row] − 128 · Σ_j W1[row, interaction_col_j]`, folded at export — exact, zero runtime cost
    - Incremental maintenance: each feature flip updates accumulator lane, `S_k ±= v_{i,k}`, `Q_k ±= v_{i,k}²`, and DOSL `lin` in O(1); a king move re-indexes the mover's perspective — full refresh of that side only; en passant flips mover pawn + captured pawn off-square; side-to-move change swaps concat order and `lin[stm]` only, no recomputation

## 4. Subnet Selection & Bucketing Logic
- **Routing Factor**: total men on board, kings included (range 2..32 by chess law — promotions convert, never clone)
- **Bucket Selection Logic** (truncating integer division, clamped):
  `m = clamp(men, 2, 32); Index = clamp((m - 1) / 4, 0, 7)`
  Start position: m=32 → bucket 7. Bare kings: m=2 → bucket 0. All 8 buckets reachable. Soft interpolation (experiment flag, default OFF): `t = ((m-1) - 4·b) / 4 ∈ [0,1)`, `eval = (1-t)·head[b] + t·head[min(b+1, 7)]` — at b=7 the clamp makes both blend terms the same head, so purity holds by the identical-head identity
- **Number of Buckets**: `8` (Main Subnets `0` through `7`)
- **Combined Perspective State** (concat order pinned): `[acc_stm(768), Î_stm(32), acc_nstm(768), Î_nstm(32)]` = `[1600]`, fed to the selected Main Subnet

## 5. Main Subnet Architecture

| Layer Index | Layer Type | Input Shape | Output Shape | Activation / Operation | Fixed-Point Type |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **L1** | Dense Linear | `[1600]` | `[16]` | None — one `VPDPBUSD` u8×i8 pass over all 1600 slots (accumulator slots unsigned, interaction slots +128 zero-point-encoded with the bias-folded correction); worst-case dot `1600 × 127 × 127 = 25,806,400`, 83× int32 headroom | `FP<i32>` |
| **L2** | Activation + Requant | `[16]` | `[16]` | SCReLU in i32, store requantized i8 | `FP<i8, 127>` |
| **L3** | Dense Linear | `[16]` | `[32]` | None | `FP<i32>` |
| **L4** | Activation + Requant | `[32]` | `[32]` | SCReLU in i32, store requantized i8 | `FP<i8, 127>` |
| **L5** | Dot Product | `[32]` | `[1]` | Output Dot Product | `FP<i32>` |

## 6. Output Conversion & Post-Processing
- **DOSL Linear Head** (parallel branch, not summed with the main output): per-feature scalar weights (`FP<i16, 32>`) over the same 24,576 index space, exact **int32** accumulator per perspective (max 32 × 32,767 = 1,048,544), `cp = lin[stm] / 32`. qsearch stand-pat reads it without running the Main Subnet
- **Perspective Average Shortcut**: None
- **Output Addition**: None (bucket head output only)
- **Final Rescaling Formula** (int64 intermediate — int32 multiply would wrap at realistic multipliers; Multiplier/Denominator map the head output to the sigmoid(cp/400) training scale):
  $$
  \text{Value} = \frac{\text{int64}(in) \times \text{Multiplier}}{\text{Denominator}}
  $$
- **Final Return Type**: Signed Integer (`int32`) / Centipawns
