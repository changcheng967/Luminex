# Luminex NNUE v1 — gen768 (the shipped architecture)

Status: **shipped** — default net family since v6.1.0 (Luminex 6.2.0 ships
`luminex_sf1_i8.nnue`, a gen768 fine-tuned on SF-relabel data). This is the
architecture the rest of the docs call "v1" when discussing v2 levers.

## Shapes

```
Features        HalfKAv2_hm, 24576 per perspective, at most 32 active
FT              24576 -> 768 per perspective (EmbeddingBag sum + bias)
Concat          stm perspective ++ nstm perspective  -> 1536
L2              1536 -> 16
L3              16 -> 32
Out             32 -> 1, output multiplied by 300 (centipawns)
```

## Activations

SCReLU (clamp to [0,1], then square) after the concat, after L2, and after
L3. The squaring of each accumulator lane is the interaction generator:
every lane is a learned quadratic form over the active features.

## Quantization

- File format LNN1: float32 feature transformer, float32 tail.
- Engine RAM: FT weights int16 at scale 8192; accumulator float32 (an int16
  saturating fallback exists but can silently corrupt — v2 replaces it with
  range-constrained training).
- Tail int8 at weight scale 64 with requant `min(v >> 6, 127)` (floor, not
  rounded — the rounding fix is a v2 item).
- Quantized export: `quantize_i8.py` -> LNI8.

## Training data contract

fen <TAB> cp lines, cp column **white-relative**, targets flipped to
stm-relative at featurize time. Filter: |cp| < 800, ply 8-200.

## Training recipe (current best)

Warm start from a gen768 checkpoint, power-2.6 loss in sigmoid(cp/400)
space, AdamW with amsgrad, batch 131072, cosine LR 1e-4, 2-8 epochs over
hundreds of millions of unique positions (never many epochs over a small
set — see the 105-epoch incident in DEVLOG). Validation: FEN-hash holdout
with per-epoch val MAE and a train-val gap alarm.
