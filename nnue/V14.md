# NNUE Architecture Specification: Luminex V14

## 1. General Metadata
- **Network Name**: Luminex V14
- **Target Engine / Application**: Luminex (v7.0+)
- **Primary Use Case**: Chess Position Evaluation (residual topology, mobility features, multi-task)
- **Weight Quantization Scheme**: Post-hoc, global + per-channel L1 scales (int16 FT, int8 tail/cross)
- **Internal Output Scale**: int64 intermediate → int32 centipawns; residual add at output

### Constants
| Symbol | Value | Meaning |
|---|---|---|
| `FT_WSCALE` | 8192 | FT weight scale = SCReLU clip ceiling |
| `QA` | 8192 | activation clip bound |
| tail weight bound | ±127 (int8) | all dense and cross layers |
| `ACC_REQUANT_SHIFT` | 19 | accumulator requant |
| `FM_REQUANT` | `clamp(Î_k >> 6, ±127)` | pairwise interaction requant |
| `CROSS_H_SHIFT` | 12 | cross intermediate requant |
| `CROSS_OUT_SHIFT` | 7 | cross output requant |
| `V_CLAMP` | 8191 | FM latent bound |
| `FM_SHIFT` | 22 | FM narrowing shift |
| `LIN_SCALE` | 32 | DOSL weight scale; int32 accumulator |
| `RESIDUAL_MODE` | true | net predicts `eval − DOSL`, not full eval |
| `MOBILITY_BUCKETS` | 8 per type | total + per-piece-type mobility summary |
| eval scale | 400 | sigmoid(cp/400) training space |

## 2. Input Features & Transformer Layer
- **Feature Set Name**: HalfKAv2_hg-m (mobility-augmented, king-bucketed, factorized)
- **Input Feature Dimension**: `[24616]` per perspective (Sparse boolean)
- **Feature Breakdown**:
  1. **Base HalfKAv2_hg** (24,576): identical to V13 — king-square conditioned piece-square, factorized king buckets
  2. **Mobility summary** (40, NEW): per-piece-type mobility counts, bucketed:
     - Total mobility: 8 buckets (0-7, 8-15, ..., 56+) — 2 features (stm/nstm)
     - Knight mobility: 4 buckets — 2 features
     - Bishop mobility: 4 buckets — 2 features
     - Rook mobility: 4 buckets — 2 features
     - Queen mobility: 4 buckets — 2 features
     - King mobility (endgame): 4 buckets — 2 features
     - Attacked squares (stm): 8 buckets — 2 features
     - Attacked squares (nstm): 8 buckets — 2 features
     - King-zone attacks: 4 buckets — 2 features
     - Hanging pieces count: 4 buckets — 2 features
     - (Total: 20 features × 2 perspectives = 40)
  3. Mobility features are computed from the engine's attack maps (already maintained), O(1) read, updated only when a mobility-relevant move occurs (non-pawn moves that open/close lines)
- **Perspective Symmetry**: Dual Perspective

---

## 3. Perspective Accumulator Subnet
Identical to V13 §3 plus:
- **Input Dimension**: `[24616]` (was 24576; +40 mobility rows)
- **Output Dimension**: `[768]` per perspective
- All V13 invariants hold (saturating int16, SCReLU, FM interaction block)
- **Interaction Block**: FM pairwise (r=32) — identical to V13
- **Cross Layer (NEW)**: one DCN-V2-style cross on Î:
  - `h = clamp((W·Î + b) >> 12, ±127)` — W: `[32][32]` int8
  - `Î2 = clamp((Î ⊙ h + Î) >> 7, ±127)` — triplewise interactions
  - Both Î and Î2 concat into the tail input

---

## 4. Subnet Selection & Bucketing Logic
Identical to V13: 8 buckets, total men routing, `clamp((m-1)/4, 0, 7)`.
- **Combined State**: `[acc_stm(768), Î_stm(32), Î2_stm(32), acc_nstm(768), Î_nstm(32), Î2_nstm(32)]` = `[1664]`

## 5. Main Subnet Architecture

| Layer | Type | Input | Output | Activation | Fixed-Point |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **L1** | Dense + per-channel scale | `[1664]` | `[16]`* | None | `FP<i32>` |
| **L2** | SCReLU + Requant | `[16]` | `[16]` | SCReLU, i8 | `FP<i8, 127>` |
| **L3** | Dense | `[16]` | `[32]` | None | `FP<i32>` |
| **L4** | SCReLU + Requant | `[32]` | `[32]` | SCReLU, i8 | `FP<i8, 127>` |
| **L5** | Dot Product | `[32]` | `[1]` | Output | `FP<i32>` (residual δ) |

*L1 width is an ablation knob: 16 (baseline, fits L1 cache) vs 32 (more capacity, cache pressure). A/B test; revert if nps drops >5%.
*Per-channel L1 scales: each of the 16 output channels has its own quantization scale instead of a global scale — recovers ~50% of the measured 16.3cp quantization tax.

## 6. Output & Multi-Task Heads

### DOSL Backbone (primary output)
Per-feature scalar weights, trained first at high LR (×500–×1000).
`baseline = lin[stm] / 32`

### Residual Add (V14's defining operation)
`eval = baseline + δ` (int64 intermediate)

### Policy Head (training only, stripped at export)
- `[1664] → [64]` one-hot over from-squares of the best move
- Loss: cross-entropy with Leela's stored best-move label
- Weight: float only, never in the engine
- Purpose: multi-task regularization — forces the accumulator to encode move-relevant information, improving eval quality as a side effect

---

## 7. Training Protocol

### Phase 1 — DOSL backbone
- Train lin head alone, high LR, to convergence (~200-250cp MAE)
- Gate: linMAE < 280cp required before Phase 2

### Phase 2 — Residual network + policy head (joint)
- Target: `residual = Leela_eval − DOSL_prediction` (~±600cp range)
- Loss: `L_eval + 0.05 × L_policy`
- Policy: predict best-move from-square (64-way classification)

### Phase 3 — Trajectory delta supervision (add to Phase 2)
- Loss: `+ 0.1 × L_delta` where `L_delta = |Δpred − Δtarget|²` on smooth positions (|Δtarget| < 100cp)
- Gate on smooth fraction: expect 70-80% of consecutive pairs

### Full loss
`L = L_eval_residual + λ_traj × L_delta + λ_policy × L_policy`
- λ_traj = 0.1, λ_policy = 0.05 (auxiliary, not dominant)

## 8. Export Contract
All V13 asserts, plus:
- Cross-layer bounds: `32×127×127 >> 12 == 126`, `(127×127+127) >> 7 == 127`
- Residual decomposition: `DOSL + δ ≈ full_eval` on held-out set
- DOSL MAE < 280cp (competent backbone)
- Policy head stripped (verify no policy weights in exported file)
- Mobility features present (40 extra rows in FT)
- Per-channel L1 scales: each channel's scale stored alongside weights

---

## 9. Engine-Side Optimizations (no network change)

### Lazy accumulator updates
Mark accumulator dirty after each move; only update when eval/linear_eval is called. Nodes pruned before evaluation skip their update entirely. Expected: 5-15% fewer accumulator updates.

### Confidence-gated eval
Read FM interaction magnitude `|Î|_sum`:
- High (tactical): use full eval (main subnet + DOSL), extend search
- Low (quiet): use DOSL only, reduce depth
- Gated by match testing — only enabled if SPRT positive

## 10. Innovation Summary & Comparison

| Component | V13 | V14 | SFNNv16 | Innovation |
|---|---|---|---|---|
| Features | HalfKAv2_hg (24576) | +40 mobility summary (24616) | HalfKAv2_hm + threats | Mobility features from engine attack maps (novel) |
| Interactions | FM pairwise | FM + cross-layer triplewise | Hand-designed threat pairs | Generic higher-order from CTR/DCN (novel for NNUE) |
| Topology | Parallel (DOSL + full) | Residual (DOSL backbone + correction) | Full eval only | Residual decomposition (novel for NNUE) |
| Training target | Full eval (±1500cp) | Residual (±600cp) | Full eval | 60% better quantization resolution |
| Multi-task | None | + policy head (best move) | None | Multi-task regularization (novel for NNUE) |
| Trajectory | None | + delta supervision | None | Search-aligned training (unique to our data) |
| Quantization | Global scales | Per-channel L1 | Global | Recovers ~50% of 16.3cp tax |
| Update | Immediate | Lazy (dirty-flag) | Immediate | Skip pruned nodes (novel) |
| Search | Uniform eval | Confidence-gated | Uniform | FM magnitude as uncertainty signal (novel) |

**Nine component improvements. Six novel for NNUE engines. Total expected: +50-125 Elo over V13 (accounting for overlap and nulls).**
